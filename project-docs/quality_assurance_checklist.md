# 品質保証チェックリスト (Quality Assurance Checklist)

本チェックリストは、プロジェクトで作成されるすべての学習記事・解説ドキュメント・過去問解法コンテンツが、IPA公式の品質基準および技術的正確性を満たしているかを検証するための **Definition of Done (DoD)** 基準書です。

---

## 1. 5大品質検証カテゴリ

### 1.1 IPA公式用語完全合致 (Strict Terminology)
- [ ] IPA公式シラバス（Ver.2.1）および 科目A-2追補版（Ver.4.0）に定義された公式用語と表記揺れがないこと（例: `共通鍵暗号` , `デジタル署名`, `送信元検証`）。
- [ ] 業界俗称や独自の略称を使用せず、IPA試験の正解選択肢・採点基準で使用される標準用語を採用していること。

### 1.2 一次情報参照とトレーサビリティ (Authority & Provenance)
- [ ] NIST SP 800シリーズ、CRYPTREC暗号リスト、RFC、IPA公式ガイドラインなどの公式一次情報へのハイパーリンクが明記されていること。
- [ ] 出典の根拠となる法令・規格番号（例: `ISO/IEC 27001`, `NIST SP 800-207`, `JIS Q 27001`）が正確に引用されていること。

### 1.3 午後記述試験対策キーワード強調 (Exam Answer Keyword Highlighting)
- [ ] 午後記述試験（科目B）で模範解答となる必須キーワードが太字 (`**キーワード**`) や引用ブロックで視覚的に強調されていること。
- [ ] 単なる知識説明にとどまらず、「設問で問われた際の30字〜40字の要約表現例」が提示されていること。

### 1.4 技術的正確性とセキュリティ標準の検証 (Technical Integrity)
- [ ] CRYPTREC等で非推奨または運用上の注意が指定された暗号方式（DES, 3DES, MD5, SHA-1, RC4等）を現代の安全な暗号として紹介していないこと。
- [ ] プロトコルシーケンス（TLSハンドシェイク、SAML認証フロー、OAuth 2.0認可等）が正確な Mermaid 図で記述されていること。

### 1.5 パス記法とMarkdownフォーマット規約 (Link Integrity)
- [ ] ローカル依存の絶対パス (`file:///workspace/...`, `file:///root/...`) が排除され、すべて正しい相対パスで記述されていること。
- [ ] GitHub Flavored Markdown 構文（コードブロックの言語指定、アラート `> [!NOTE]`）に準拠していること。

## 2. 品質ゲート (Quality Gate) 判定基準

ドキュメントを `main` ブランチへマージするためには、上記 5 大カテゴリのチェック項目がすべてチェック (`[x]`) されている必要があります。
