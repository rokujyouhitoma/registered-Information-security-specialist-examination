# 文書管理台帳および文書管理規約 (Document Ledger & Management Rules)

Document ID: `MNG-01-document_ledger`

---

## 1. 概要・目的 (Overview & Purpose)

本ドキュメントは、**情報処理安全確保支援士試験 対策学習リポジトリ**において作成・管理される全てのドキュメント（要求定義書、開発・運用プロセスガイド、学習コンテンツ成果物、一次情報参照資料、Issue台帳等）の位置づけ、保管場所、管理責任、更新トリガーおよび追跡性（トレーサビリティ）を規定・一元管理するための台帳です。

本規約により、プロジェクト内のすべてのドキュメントの最新化、整合性維持、および役割の重複（オーバーラップ）の排除を実現します。

## 3. ドキュメント間のすみ分けと管理ルール (Demarcation & Rules)

### 3.1 成果物 (`docs/`) と 内部管理 (`project-docs/`) のすみ分け
- **`docs/` (Web公開用最終成果物)**:
  - GitHub Pages を通じて一般ユーザー（学習者）がブラウザで閲覧・検索する解説コンテンツ、過去問対策ノート、シラバス要約のみを配置します。
- **`project-docs/` (プロジェクト内部ドキュメント)**:
  - ユーザー要求定義（REQ）、文書台帳（MNG）、運用・執筆ガイドラインなど、リポジトリ管理者・執筆者が参照・更新する管理資料を配置します。

### 3.2 要求定義 (REQ) と 学習ドキュメント (`docs/`) のトレーサビリティ
- `docs/` 内の学習コンテンツを作成・更新する際は、[REQ-01-user_requirements.md](../requirements/REQ-01-user_requirements.md) に規定された「要求（REQ-01-CNT-01〜04）」に準拠していることを確認します。
- 各分野のドキュメント（暗号、ネットワーク、Webセキュリティ、インシデント対応、過去問演習）は、要求で定義されたターゲットユーザー・ユースケースを満たすよう体系的に構成します。

### 3.3 一次情報 (`references/`) と 解説ドキュメント (`docs/`) の連携
- 解説ドキュメント（`docs/*.md`）で言及する公式用語・技術規格（例: NIST SP 800-53, RFC 8446, IPA安全なウェブサイトの作り方）は、必ず [references/README.md](../../references/README.md) に記載された一次情報と相互リンクまたは参照関係を明記します。
