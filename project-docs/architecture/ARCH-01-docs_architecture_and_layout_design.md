# `docs/` ディレクトリ構成・レイアウト設計方針書 (Documentation Architecture & Layout Design Specification)

本ドキュメントは、**情報処理安全確保支援士試験コンテンツ制作・学習管理プロジェクト**における Web 公開成果物（GitHub Pages / MkDocs）である `docs/` ディレクトリの**ディレクトリ構造、ページ内レイアウト設計方針、ナビゲーション構造、および執筆コンポーネント標準**を定義した設計仕様書です。

---

## 🎨 4. デザイン標準 & 装飾ガイドライン (UI/UX Guidelines)

### (1) GitHub Alert Callouts の使用規約
視覚的なメリハリをつけるため、コンテンツ内で以下の Alert 要素を使い分けます。
- **`> [!NOTE]`**: 章の学習目標、前提知識、導入解説
- **`> [!TIP]`**: 試験解法テクニック、暗記のコツ、計算問題のショートカット
- **`> [!IMPORTANT]`**: **午後記述試験の模範解答キーワード・採点基準**
- **`> [!WARNING]`**: 誤解しやすいポイント、非推奨の旧規格（例: DES/MD5の脆弱性）
- **`> [!CAUTION]`**: 実務運用上のセキュリティリスク、脆弱性情報

### (2) 可視化 (Mermaid Diagram) の標準化
文章だけの解説を避け、プロトコルシーケンスやネットワーク構成図はすべて **Mermaid.js** で記述します。
- **シーケンス図 (`sequenceDiagram`)**: TLSハンドシェイク、OAuth 2.0認可フロー、HTTPリクエスト/レスポンス
- **フローチャート (`flowchart TD`)**: インシデント対応手順、マルウェア感染調査フロー
- **クラス/エンティティ図 (`erDiagram`)**: DB設計、PKI証明書検証チェーン

## 🔗 5. パス表記 & 相互参照ルール

1. **相対パス指定の厳格化**:
   - `docs/` 配下から別ドキュメントや `references/`, `glossary/` を参照する場合、必ず同一リポジトリ内の相対パス (`../`, `./`) を使用します。
   - × 非推奨: `file:///workspace/...`, `/docs/...`
   - ○ 推奨: `../syllabus/syllabus_detail.md#3-5`
2. **アンカーリンクの明記**:
   - シラバス番号へのリンクは `#3-5-ネットワークセキュリティ` のように見出しアンカーを付与し、ダイレクトジャンプ可能にします。
