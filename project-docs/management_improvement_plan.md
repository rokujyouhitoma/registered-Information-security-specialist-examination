# プロジェクト管理・運用改善提案書 (Project Management Improvement Proposal)

本ドキュメントは、**情報処理安全確保支援士試験コンテンツ制作・学習管理プロジェクト**（`registered-Information-security-specialist-examination`）のプロジェクトマネージャー（PM）視点に基づき、今後高品質な学習コンテンツを効率的かつ持続可能に制作・管理するために**改善すべき事項および新たに定義すべき標準・ルール（10選）**を検討・整理したものです。

---

## 📑 各検討項目の詳細

### 1. コンテンツ制作ロードマップ & WBS の定義
- **現状課題**: `docs/syllabus_detail.md` (Ver.2.1) および `docs/syllabus_tsuiho_detail.md` (追補版) によりシラバスは完全準拠されたが、どの分野から具体的に解説記事・過去問解説・要点ノートを作成するかの全体スケジュール・優先度が未定義。
- **PM改善策**:
  - 試験の出題比率（午後試験で頻出の「暗号・PKI」「Webアプリケーションセキュリティ」「ネットワークセキュリティ」「インシデントハンドリング/フォレンジック」）に基づき、**Phase 1（最優先）**, **Phase 2（標準）**, **Phase 3（追補・基礎）** の制作WBSを定義する。

### 2. マルチエージェント役割分担 (RACIマトリックス) の明文化
- **現状課題**: `yuzora` リポジトリから 10 種のエージェント定義（`.agents/agents/*.agent.md`）を取り込んだが、各エージェントがどのドキュメントの執筆・レビューを担当するかの運用マニュアルがない。
- **PM改善策**:
  - `project-docs/agent_roles.md` を作成し、各エージェントの専門領域と担当タスクを明記する。
    - **Database Specialist (DB)**: `3-1` 暗号利用, `3-8` アカウント管理, データベースセキュリティ記事の執筆・検証
    - **Network Specialist (NW)**: `3-5` ネットワーク管理, 追補版ネットワーク方式の執筆・検証
    - **Information Security Specialist (SC)**: 全体監修・セキュリティ設計・インシデント対応の検証
    - **Systems Auditor (AU)**: `1-5` 情報セキュリティ監査, コンプライアンスの検証
    - **Project Manager (PM)**: WBS管理, Issue管理, 進捗・品質チェック

### 3. 記事・問題コンテンツの品質保証プロセス (DoD) の策定
- **現状課題**: 学習コンテンツに誤った情報（例: 推奨されない旧暗号方式の推奨、ハルシネーション、表記揺れ）が紛れ込むリスクがある。
- **PM改善策**:
  - 記事を `docs/` にマージ・公開するための Definition of Done (DoD: 完成定義) を策定する。
    - [ ] IPA公式シラバスの用語と100%表記が合致しているか
    - [ ] CRYPTREC暗号リストやNIST SP 800等の一次情報への参照リンクがあるか
    - [ ] 午後記述式試験の採点基準に適合したキーワードが強調表示されているか

### 4. 絶対パス排除と相対パス表記ルールの厳格化
- **現状課題**: ローカル環境依存の絶対パス（`file:///workspace/...`）がドキュメント内に混入し、手動修正が必要となった。
- **PM改善策**:
  - `project-docs/writing_guide.md` に「相対パス強制ルール」を明記。
  - GitHub リポジトリルートからの相対パス（`../references/...`, `../../docs/...`）のみを許可し、絶対パスの混入を自動検知するリンター/チェック処理を定義。

### 5. Issue 採番・追跡・自動化ルールの強化
- **現状課題**: Issue 作成時の ID 重複や手動追記の手間が発生しやすかった。
- **PM改善策**:
  - Issue の作成・クローズ時の ID 自動採番手順を標準化。
  - スクリプト `scripts/manage_issues.py` を作成し、`issues/` 内のファイルから台帳 `issues/README.md` を自動更新・整合化できるようにする。

### 6. GitHub Pages 自動デプロイ & リンク切れ検証 CI の構築
- **現状課題**: `README.md` に GitHub Pages 公開の目的が掲げられているが、自動デプロイやリンク切れ検知が未設定。
- **PM改善策**:
  - `.github/workflows/deploy.yml` および `.github/workflows/link-check.yml` を作成し、`main` ブランチへのプッシュ時に MkDocs / GitHub Pages への自動デプロイとデッドリンクの自動検知を行う。

### 7. 一次情報 (`references/`) および一次検証スクリプトの管理規約
- **現状課題**: PDFから抽出した中間テキストや検証スクリプトがルートや `scratch/` に散逸し、不要ファイルが蓄積するリスク。
- **PM改善策**:
  - `references/` には原則として公式一次情報（PDF・公式ドキュメント）のみを保管。
  - テキスト変換済みの分析データや一時スクリプトは `scratch/` に統一し、`.gitignore` にスクラッチ成果物の整理ルールを明記。

### 8. 試験種別 (科目A/科目B)・難易度メタデータ (Frontmatter) の定義
- **現状課題**: 作成されたドキュメントが「知識暗記向け（科目A-2）」か「実務・記述分析向け（科目B）」かが判別しづらい。
- **PM改善策**:
  - 全学習ドキュメントの冒頭に YAML Frontmatter を導入する。
    ```yaml
    ---
    title: ネットワークセキュリティ対策
    syllabus_code: 3-5
    exam_type: [A-2, B]
    difficulty: Advanced
    tags: [TLS, IPsec, WAF, 午後記述頻出]
    ---
    ```

### 9. 全用語・略語を一元管理する用語辞書 (`docs/glossary.md`) の構築
- **現状課題**: 暗号、プロトコル、フレームワーク等の略語（GCM, AEAD, SOAR, STIX, SCRM, SBOM等）が各ドキュメントに分散している。
- **PM改善策**:
  - シラバス記載の全用語例および略語をアルファベット順・五十音順にインデックス化し、各用語の解説と該当シラバス番号への相互リンクを持つ `docs/glossary.md`（支援士試験 総合用語集）を作成する。

### 10. IPAシラバス改定追従プロセス & 変更履歴 (Changelog) の運用
- **現状課題**: IPAがシラバス追補版（例: Ver.4.0 変更箇所表示版）を改定した際、既存コンテンツのどこを修正すべきかの追従フローがない。
- **PM改善策**:
  - IPA公式の年次改定（12月〜4月）を検知した際の「シラバス差分インポート手順」を `project-docs/processes/syllabus_update_process.md` として定義し、コンテンツの変更履歴を `CHANGELOG.md` で管理する。
