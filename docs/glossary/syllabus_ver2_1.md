#### <a id="機密性(confidentiality)"></a>機密性(Confidentiality)
- **解説**: 許可された正当な人やシステムだけが情報にアクセスできる状態を保つことです。情報セキュリティの基本要素であるCIA（機密性・完全性・可用性）の一つで、個人情報や企業の秘密の漏洩を防ぎます。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md)

#### <a id="完全性(integrity)"></a>完全性(Integrity)
- **解説**: 情報やデータが改ざんや破壊をされず、正確かつ完全な状態で維持されていることです。デジタル署名や暗号学的ハッシュ値を用いて非正規な書き換えや改ざんを検知・防止します。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md)

#### <a id="可用性(availability)"></a>可用性(Availability)
- **解説**: 認可された利用者が、必要な時に遅滞なく情報やシステムを利用できる状態を維持することです。サーバーや回線の冗長化、バックアップ、DoS攻撃対策によりシステムの継続的運用を保障します。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md)

#### <a id="真正性(authenticity)"></a>真正性(Authenticity)
- **解説**: 情報や送信者・利用者が本物であり、なりすましや偽造・詐称が行われていないことを証明・確認できる状態のことです。デジタル証明書や多要素認証 (MFA) によって担保されます。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md)

#### <a id="責任追跡性(accountability)"></a>責任追跡性(Accountability)
- **解説**: 利用者の操作やシステムの変更履歴が監査ログ等に正確に記録され、誰が何を行ったかの責任を事後的に明確に特定・証明できる特性のことです。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md)

#### <a id="否認防止(non-repudiation)"></a>否認防止(Non-repudiation)
- **解説**: データの作成や送信が行われた事実を第三者に証明し、後からその動作を行った事実を否認できないようにする特性です。公開鍵暗号に基づくデジタル署名やタイムスタンプで実現されます。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md)

#### <a id="信頼性(reliability)"></a>信頼性(Reliability)
- **解説**: システムやネットワークが設計・意図された仕様通りに、エラーや予期せぬ欠陥なく正確かつ確実に処理を実行完了する状態のことです。
