# シラバスVer.2.1 用語辞書 (Glossary for Syllabus Ver.2.1)

本辞書は、IPA公式シラバス Ver.2.1に登場するすべての「用語例・キーワード」を網羅抽出し、定義および関連シラバス項目への参照リンクを整理したナレッジベースです。

---

## 🔤 用語一覧と定義

### 1. 情報セキュリティマネジメント (1-1 〜 1-7)

#### ISMS (Information Security Management System) / BCMS
- **概要**: 組織の情報資産の機密性・完全性・可用性をバランスよく維持・管理するためのマネジメント体系 (JIS Q 27001 / ISO/IEC 27001)。事業継続マネジメントシステムは BCMS (JIS Q 22301)。
- **シラバス参照**: [1-1 情報セキュリティ方針の策定](../syllabus_detail.md#1-1-情報セキュリティ方針の策定)

#### STRIDE分析 / アタックツリー分析 (ATA)
- **概要**: 脅威の特定・分類モデル（S:なりすまし, T:改ざん, R:否認, I:情報漏えい, D:サービス拒否, E:権限昇格）および攻撃経路をツリー構造で可視化・分析する手法。
- **シラバス参照**: [1-2 情報セキュリティリスクアセスメント](../syllabus_detail.md#1-2-情報セキュリティリスクアセスメント)

#### 情報セキュリティ監査 (内部監査 / 外部監査)
- **概要**: 組織の情報セキュリティマネジメントや運用が、方針や基準に準拠しているかを独立した客観的立場で検証・評価し、保証または助言を与える活動。
- **シラバス参照**: [1-6 情報セキュリティ監査](../syllabus_detail.md#1-6-情報セキュリティ監査)

---

### 2. システムの企画・設計・開発・運用 (2-1 〜 2-8)

#### Secure by Design / Security by Default
- **概要**: システムの企画・設計フェーズからセキュリティ要件を組み込み（Secure by Design）、初期設定状態で最も安全な設定を提供する（Security by Default）開発原則。
- **シラバス参照**: [2-1 安全な要件定義](../syllabus_detail.md#2-1-安全なシステム要件定義)

#### DevSecOps
- **概要**: ソフトウェア開発 (Dev) と運用 (Ops) のライフサイクル全体に、自動化されたセキュリティテストや静的・動的解析 (SAST/DAST) を継続的に統合する開発運用モデル。
- **シラバス参照**: [2-4 安全なプログラム開発](../syllabus_detail.md#2-4-安全なプログラム開発)

#### 脆弱性診断 (SAST / DAST / ペネトレーションテスト)
- **概要**: ソースコード解析 (SAST)、実行中アプリ検査 (DAST)、および疑似攻撃者による侵入テスト (ペネトレーションテスト) によりシステム内の脆弱性を検出・評価する手法。
- **シラバス参照**: [2-7 脆弱性管理](../syllabus_detail.md#2-7-脆弱性管理)

### 3. セキュリティ技術要素 (3-1 〜 3-11)

#### AEAD (Authenticated Encryption with Associated Data / 認証付き暗号)
- **概要**: 共通鍵ブロック暗号において、暗号化（秘匿性）とメッセージ認証コード（完全性・送信元認証）を同一アルゴリズムで同時に実現する暗号方式（GCM, CCM 等）。
- **シラバス参照**: [3-1 暗号技術](../syllabus_detail.md#3-1-暗号技術)

#### AES (Advanced Encryption Standard)
- **概要**: 米国NISTが標準化した現代の代表的な共通鍵ブロック暗号。鍵長128/192/256ビット、ブロック長128ビットを採用。
- **シラバス参照**: [3-1 暗号技術](../syllabus_detail.md#3-1-暗号技術)

#### GCM (Galois/Counter Mode)
- **概要**: AES等のブロック暗号モードの一種。カウンターモード (CTR) とガロア体演算による認証タグ生成を組み合わせたAEAD方式。
- **シラバス参照**: [3-1 暗号技術](../syllabus_detail.md#3-1-暗号技術)

#### HMAC (Hash-based Message Authentication Code)
- **概要**: 共通鍵と暗号学的ハッシュ関数（SHA-256等）を組み合わせて生成するメッセージ認証コード。改ざん検知と送信元認証に利用。
- **シラバス参照**: [3-2 キーマネジメントと公開鍵インフラ](../syllabus_detail.md#3-2-キーマネジメントと公開鍵インフラ)

#### PKCE (Proof Key for Code Exchange)
- **概要**: OAuth 2.0認可コードグラントフローにおいて、認可コード横取り攻撃を防ぐため動的な検証コード (code_verifier / challenge) を用いる拡張仕様。
- **シラバス参照**: [3-3 認証技術](../syllabus_detail.md#3-3-認証技術)

#### SAML 2.0 (Security Assertion Markup Language)
- **概要**: XMLをベースに、IdP (Identity Provider) と SP (Service Provider) 間で認証・認可情報をトークン（アサーション）として伝送するSSO標準。
- **シラバス参照**: [3-3 認証技術](../syllabus_detail.md#3-3-認証技術)

---


#### SPF (Sender Policy Framework)
- **概要**: 送信元ドメインのDNS (TXTレコード) に正規の送信メールサーバーIPアドレスを宣言し、受信側でIPアドレスを照合して成りすましを検証する方式。
- **シラバス参照**: [4-4 メールセキュリティ](../syllabus_detail.md#4-4-メールセキュリティ)

#### TLS 1.3 (Transport Layer Security)
- **概要**: トランスポート層の暗号化プロトコル。ハンドシェイクの1-RTT化、非推奨暗号（RSA鍵交換やCBCモード）の廃止、0-RTTデータ送信等を導入。
- **シラバス参照**: [4-2 ネットワーク層・トランスポート層セキュリティ](../syllabus_detail.md#4-2-ネットワーク層トランスポート層セキュリティ)

---

### 3. エンドポイント & システム運用セキュリティ

#### EDR (Endpoint Detection and Response)
- **概要**: PCやサーバー等のエンドポイントの挙動ログを常時監視し、侵入後の脅威（マルウェアの横展開等）を即座に検知・孤立化・調査するソリューション。
- **シラバス参照**: [5-4 エンドポイントセキュリティ](../syllabus_detail.md#5-4-エンドポイントセキュリティ)

#### SIEM (Security Information and Event Management)
- **概要**: ネットワーク機器、サーバー、FW、セキュリティソリューションの各種ログを統合収集・相関分析し、潜在的な脅威や不正アクセスを自動検知するシステム。
- **シラバス参照**: [6-2 セキュリティ運用監視](../syllabus_detail.md#6-2-セキュリティ運用監視)
