# [ADR-02] 循環的複雑度（サイクロマティック複雑度）の閾値設定と自動検知の導入

## 日付
2026-08-07

## ステータス
Accepted (承認済み・実装完了)

## コンテキスト (Context)
本プロジェクト（情報処理安全確保支援士試験 対策ドキュメント & ナレッジベース / フルスクラッチ全文検索ポータル）の規模拡大に伴い、JavaScript 検索エンジンコア (`CustomSearchEngine`, `Tokenizer`, `SemanticScorer` 等) およびインデックス構築・自動テスト用スクリプト群の分岐や制御フローが複雑化し、可読性・テスト容易性・保守性が低下するリスクが生じていました。

コードの品質を定量的かつ客観的に維持し、複雑すぎる関数（制御フロー分岐・ネストが多すぎる構造）の発生を自動検知してリファクタリングを促進する設計基準と検証フレームワークが必要です。

## 決定事項 (Decision)
1. **循環的複雑度 (Cyclomatic Complexity: $V(G)$) 閾値の設定**:
   - 関数の循環的複雑度の目標上限値を **`10`** と規定する。
   - 分岐数（`if`, `else if`, `for`, `while`, `case`, `catch`, 複合論理演算子 `&&`, `||`, 三項演算子 `? :`）が 10 を超える関数は、原則として単一責任化（関数分割・ヘルパー抽出）を行ってリファクタリングする。
   - 計算・描画やデータパースの性質上、構造的に複雑度 10 を超えることが不可避な関数については、コード内に明示的なコメントおよび本 ADR にて例外措置の理由を記載することを義務付ける。

2. **自動検証スクリプトの導入**:
   - Python 解析スクリプト `scripts/verify_cyclomatic_complexity.py` を導入し、`src/js/` 配下のソースコードに含まれるすべての関数について循環的複雑度を静的解析・自動アサーション検証する。
   - `npm test` パイプラインの一環として自動実行し、リプレースや新機能追加時に閾値超過バグが紛れ込まないように品質ガードを敷く。

## 実装結果 (Consequences)
- `scripts/verify_cyclomatic_complexity.py` を作成し、全自動テスト（`npm run test:complexity`）へ追加統合。
- `CustomSearchEngine` および `SemanticScorer` 内の各種処理をリファクタリング・ヘルパー分離し、循環的複雑度 10 以下に最適化。
- リポジトリの保守性・可読性・単体テスト容易性が大幅に向上し、不具合の防止と堅牢なアーキテクチャが実現された。
