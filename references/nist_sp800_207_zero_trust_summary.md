# NIST SP 800-207 ゼロトラスト・アーキテクチャ (Zero Trust Architecture) 要約参照ガイド

出典: [NIST SP 800-207 Zero Trust Architecture](https://csrc.nist.gov/publications/detail/sp/800-207/final)

---

## 1. ゼロトラストの基本概念
ゼロトラスト (Zero Trust) とは、ネットワーク境界の内側・外側を問わず、全てのアクセス要求を「デフォルトで信頼しない」というセキュリティコンセプトである。「常に検証せよ (Never Trust, Always Verify)」を原則とする。

---

## 2. ゼロトラストの7大基本原則 (7 Basic Tenets)
1. **全てのデータ源とコンピューティングサービスをリソースとみなす**:
   個々のデバイス、クラウドサービス、IoT機器等を区別なく保護対象とする。
2. **ネットワークの場所に関わらず、全ての通信を保護する**:
   社内LANからのアクセスであっても、インターネット経由と同等に暗号化・認証・認可を実施。
3. **個々のリソースへのアクセスをセッションごとに許可する**:
   過去の認証結果を永続的に信頼せず、アクセス要求ごとに最小権限の原則 (Least Privilege) を適用。
4. **アクセス決定は動的ポリシーによって制御する**:
   ユーザーID、デバイスの状態（パッチ適用状況、マルウェア非感染等）、利用場所、脅威インテリジェンス等のコンテキストに基づき動的に判定。
5. **保有する全てのデバイスの健全性とセキュリティ状態を監視・測定する**:
   MDM/EDR等を通じてクライアントデバイスのコンプライアンス状態を常時アセスメント。
6. **リソースアクセスは全て事前認証・認可を経る**:
   アクセス制御ポイント (PEP) を通過しない直接アクセスを排除。
7. **資産、ネットワークインフラ、通信に関する状態情報を収集し、改善に活用する**:
   ログやテレメトリを継続的に収集し、SIEM/SOAR/UEBA等によりリアルタイム検知・分析。

---

## 3. ゼロトラスト・アーキテクチャの主要コンポーネント
- **Policy Engine (PE / ポリシーエンジン)**: アクセス許可・拒否の最終決定を行う判定エンジン。
- **Policy Administrator (PA / ポリシー管理者)**: PEの決定に基づき、アクセスセッションの確立・切断制御シグナルをPEPに送る。
- **Policy Decision Point (PDP)**: PEとPAを合わせた判定コンポーネント。
- **Policy Enforcement Point (PEP / ポリシー実行ポイント)**: ユーザーとリソースの間に位置し、通信セッションを制御・実行するゲートウェイ。
